# Functional Coverage Plan for an AXI4-Based DMA Controller

## 1. Overview

This document defines the functional coverage structure, sampling points, coverpoints, crosses, and
closure criteria used to measure whether the verification items in
[`VERIFICATION_PLAN.md`](./VERIFICATION_PLAN.md) have actually executed.

The previous single `cg_dma_coverage @(posedge tb.clk)` structure repeatedly samples values with
different meanings on every cycle. Step 4 separates coverage into three groups: transactions, the DMA
FSM, and AXI events.

## 2. Coverage Structure

- Implementation file: [`coverage.sv`](../dv/coverage.sv)

| Covergroup | Sampling | Measurement Target | Coverpoints | Crosses |
|---|---|---|---:|---:|
| `cg_dma_transaction` | Rising edge of completion/error interrupt | Configuration, addresses, and actual termination result | 8 | 3 |
| `cg_dma_fsm` | Rising edge of `tb.clk` | FSM state, state transition, `S_SETUP`, and tail branches | 4 | 0 |
| `cg_axi_event` | Rising edge of `tb.clk` with channel-specific `iff` | AWLEN, W handshake/stall, WLAST, and BRESP | 7 | 2 |
| **Total** |  |  | **19** | **5** |

Transaction coverage samples the transaction configuration and actual result once when a completion
or error interrupt occurs. FSM and AXI-event coverage use clock-based collection, with `iff`
conditions restricting sampling to cycles in which the applicable state or handshake occurs.

```systemverilog
covergroup cg_dma_transaction
    @(posedge tb.mmio.dma_done_int or posedge tb.mmio.dma_error_int);
endgroup

covergroup cg_dma_fsm @(posedge tb.clk);
endgroup

covergroup cg_axi_event @(posedge tb.clk);
endgroup
```

## 3. Transaction Coverage

### 3.1 Coverpoint

| ID | Coverpoint | Sampling Condition | Target Bins | Purpose |
|---|---|---|---|---|
| C-TX-01 | `cp_size_boundary` | DMA done/error interrupt | 1, 2, 3, 4, 12, 15, 16, 60, 64, 68, 80, 256, 1,024, 1,028, 2,048B | Check unsupported sizes, reference transfers, burst boundaries, tails, and maximum transfer |
| C-TX-02 | `cp_size_range` | DMA done/error interrupt, 4-byte multiple | `size_tiny`=4~16, `size_small`=20~256, `size_medium`=260~1,024, `size_large`=1,028~2,048B | Checks the size distribution of normal transfers |
| C-TX-03 | `cp_size_category` | DMA done/error interrupt | Below 4B / at least 4B but not divisible by 4 / divisible by 4B | Classify normal and erroneous size conditions |
| C-TX-04 | `cp_src_region` | DMA done/error interrupt | low / mid / high | Measure the distribution of source start addresses across the three memory regions |
| C-TX-05 | `cp_dst_region` | DMA done/error interrupt | low / mid / high | Measure the distribution of destination start addresses across the three memory regions |
| C-TX-06 | `cp_backpressure_class` | DMA done/error interrupt | `bp_none`=0%, `bp_low`=1~30%, `bp_medium`=31~70%, `bp_high`=71~99% | Checks stimulus across response-delay intensities |
| C-TX-07 | `cp_error_inject` | DMA done/error interrupt | off / on | Check normal BRESP and intentional SLVERR conditions |
| C-TX-08 | `cp_error_code` | DMA done/error interrupt | normal=`0x0`, size error=`0x2`, SLVERR=`0x3` | Check the actual result corresponding to the stimulus |

Transfer-size coverage is intended to check boundary values that change DUT decisions, not to cover
every number uniformly. Other valid sizes generated by constrained randomization provide additional
checks of constraint-based normal transfers and do not automatically create separate closure bins.

### 3.2 Cross

| ID | Cross | Target Combinations | Purpose |
|---|---|---|---|
| X-TX-01 | `cx_size_result` | Normal size→`0x0`; below 4B or not divisible by 4→`0x2` | Relate the transfer-size condition to the actual result |
| X-TX-02 | `cx_inject_result` | off→`0x0`/`0x2`; on→`0x3` | Relate the error-injection setting to the actual error code |
| X-TX-03 | `cx_inject_backpressure` | Error injection off/on × `bp_none`/`bp_low`/`bp_medium`/`bp_high` | Check standalone SLVERR and combined backpressure conditions |

X-TX-01 and X-TX-02 count the combinations targeted by each cross. X-TX-01 ignores the
aligned-size/SLVERR combination because X-TX-02 covers the injected error response. X-TX-03 targets
all eight combinations of error-injection and backpressure settings.

## 4. DMA FSM Coverage

### 4.1 Coverpoint

| ID | Coverpoint | Sampling Condition | Target Bins | Purpose |
|---|---|---|---|---|
| C-FSM-01 | `cp_state` | Rising edge of `clk`, reset released | `S_IDLE`, `S_SETUP`, `S_RD_ADDR`, `S_RD_DATA`, `S_WR_ADDR`, `S_WR_DATA`, `S_WR_RESP`, `S_NEXT`, `S_DONE`, `S_ERROR` | Confirm reachability of every DMA state |
| C-FSM-02 | `cp_state_transition` | Rising edge of `clk`, reset released | Normal completion, multi-burst repetition, size/BRESP errors, and error-recovery transitions | Execute normal, repeated, error, and recovery paths |
| C-FSM-03 | `cp_setup_case` | `S_SETUP && !setup_complete` | `bytes_left=1–3`, `4–15`, `16–63`, `64 or more` | Check burst-length decision branches |
| C-FSM-04 | `cp_tail_setup_case` | Remaining `S_SETUP` of a normal transfer larger than 64B | 1-beat tail=`4–15`, 4-beat tail=`16–63` | Check the remainder handling of multi-burst transfers |

`bytes_left` is sampled only in the cycle in which the `S_SETUP` burst decision actually executes.
Values retained in other states are not included in coverage. Tail setup applies only to transactions
whose original transfer size exceeds 64B, is divisible by 4, and leaves a 4–63B remainder after full
64B bursts.

## 5. AXI Event Coverage

### 5.1 Coverpoint

| ID | Coverpoint | Sampling Condition | Target Bins | Purpose |
|---|---|---|---|---|
| C-AXI-01 | `cp_awlen` | `AWVALID && AWREADY` | 0 (1 beat), 3 (4 beats), 15 (16 beats) | Check actual write-burst lengths |
| C-AXI-02 | `cp_backpressure_cfg_at_aw` | `AWVALID && AWREADY` | `bp_none` / `bp_low` / `bp_medium` / `bp_high` | Check the backpressure setting applied to each write burst |
| C-AXI-03 | `cp_w_event` | `WVALID` | accepted=`WREADY`, stalled=`!WREADY` | Check W handshakes and actual stalls |
| C-AXI-04 | `cp_stall_awlen` | `WVALID && !WREADY` | AWLEN 0 / 3 / 15 | Check actual stalls by burst length |
| C-AXI-05 | `cp_wlast_awlen` | `WVALID && WREADY && WLAST` | AWLEN 0 / 3 / 15 | Check WLAST handshakes by burst length |
| C-AXI-06 | `cp_bresp` | `BVALID && BREADY` | OKAY / SLVERR | Check actual write responses |
| C-AXI-07 | `cp_error_inject_at_b` | `BVALID && BREADY` | off / on | Check the error-injection setting at B-response time |

At the AW handshake, coverage samples the backpressure value to be applied to that write burst. Actual
stalls are classified by the AWLEN associated with observed `WVALID && !WREADY` cycles. Values other
than AWLEN 0, 3, and 15 are illegal bins because the current DUT never generates them.

### 5.2 Cross

| ID | Cross | Target Combinations | Purpose |
|---|---|---|---|
| X-AXI-01 | `cx_backpressure_awlen` | `bp_none`/`bp_low`/`bp_medium`/`bp_high` × AWLEN 0/3/15 | Check backpressure settings by burst length |
| X-AXI-02 | `cx_bresp_error_inject` | off×OKAY, on×SLVERR | Relate error injection to the actual response |

## 6. Coverage Exclusions

| Item | Treatment | Rationale |
|---|---|---|
| Unaligned address | No coverage bin | The DUT and transaction support only 4-byte-aligned accesses |
| Address outside 4 KB or overlapping regions | No coverage bin | Violates the memory range and transaction constraints |
| `AWLEN` other than 0, 3, or 15 | Illegal bin | Must not be generated by the DUT's burst-splitting rules |
| EXOKAY, DECERR, and RRESP errors | Excluded from coverage | Not generated by the DDR memory model |
| `AxSIZE`, `AxBURST`, and `WSTRB` combinations | Excluded from coverage | Used as fixed values by the DUT |

## 7. Coverage Completion Criteria

- 100% of the planned coverpoint bins and valid cross bins in all three covergroups
- Exactly one transaction-covergroup sample per transaction
- `iff` conditions that sample AW, W, and B events only in their respective handshake or stall cycles
- No illegal stimulus or meaningless cross hit introduced solely to increase coverage
- PASS results from the Scoreboard and assertions for normal transfers
- Scenario-specific records of expected UVM errors and Scoreboard results from negative tests
- Final simulation log containing transaction counts, actual random values, per-item coverage, and overall coverage
