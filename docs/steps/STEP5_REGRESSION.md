# Step 5 — Multi-Seed Backpressure Regression

## Overview

Step 4 exercised the planned size-error and BRESP SLVERR scenarios with directed tests and met their
functional coverage targets. Step 5 focuses on randomized W-channel stalls. One seed runs 36
transactions combining six backpressure probabilities and six transfer sizes, and 10 independent
simulations use seeds `1001` through `1010`.

In each run, the Scoreboard compares the complete source and destination transfer regions. Across 10
seeds, all 360 transactions passed, and the Scoreboard matched all 25,560 source words to their
destination words. The W-channel checker reported zero violations, and no data mismatch, timeout, or
UVM error occurred.

## Objective

Confirm that the DUT operates normally without data loss, timeout, or AXI4 protocol violations under
the varied backpressure timing and repeated-transfer conditions generated by different seeds, and
build a regression system that automatically detects recurrence of the W-payload, FIFO-prefetch, and
WLAST issues found and fixed in Steps 3 and 4.

## Main Changes

- Separate `dma_regression_seq` and `dma_regression_test` under `dv/uvm/regression` to distinguish the
  Step 5 repeated-verification configuration from the Step 4 functional-verification scenarios
- Configure `testbench.sv` to select the regression test through
  `+UVM_TESTNAME=dma_regression_test` and run the existing `dma_test` when no option is present
- Have `dma_regression_test` read the numeric seed from `+ntb_random_seed` and include it in the sequence and final result report
- Run 36 transactions per seed combining 0%, 10%, 30%, 50%, 70%, and 90% backpressure with 4B, 16B, 64B, 80B, 512B, and 1,028B transfer sizes
- Record the seed, backpressure probability, and transfer size in the scenario name to support failure tracing and reruns with the same seed
- Integrate the existing Scoreboard's complete transfer-region data comparison and the AXI4 W-channel A-01–A-03 assertion checker into regression evaluation
- Determine each simulation's PASS/FAIL result from 36/36 transactions, zero UVM warnings/errors/fatals, and zero assertion violations
- Do not remeasure functional coverage because closure was completed in Step 4; also exclude throughput because it is outside the project's functional/protocol verification scope

The detailed regression plan is defined in [`REGRESSION_PLAN.md`](../REGRESSION_PLAN.md).

Every transaction runs with `src_addr=0x0000`, `dst_addr=0x0800`, and `error_inject=0`. Even at the
maximum size of 1,028B, the source region `0x0000–0x0403` and destination region
`0x0800–0x0C03` do not overlap within the 4 KB memory.

Step 4 exercised the planned size-error and BRESP SLVERR scenarios with directed tests and met their
functional coverage targets. Step 5 is scoped to W-channel backpressure whose occurrence timing
changes according to a random decision on every cycle.

## VCS Configuration

Use the same VCS, UVM, and compile options as Step 4 and specify the regression test and seed in the
Run options.

- Simulator: Synopsys VCS 2025.06
- UVM version: UVM 1.2
- Compile options:

  ```text
  -timescale=1ns/1ns +vcs+flush+all +warn=all -sverilog -debug_access+all
  ```

- Run-options example:

  ```text
  +UVM_TESTNAME=dma_regression_test +ntb_random_seed=1001
  ```

Change the seed from `1001` through `1010` and run 10 simulations. Re-executing the same code with the
same seed reproduces the corresponding random backpressure conditions.

Across 10 seeds, all 360 transactions passed, and all 25,560 source words matched their destination
words. No DMA timeout or UVM warning/error/fatal occurs, and every A-01–A-03 assertion violation
count remains zero.

Although each seed executes the same 36 transactions, completion times vary from 134,045ns to
138,325ns. This demonstrates that the DDR memory model produced a different random stall sequence for
each seed and confirms that data integrity and all AXI4 W-channel assertion conditions remained valid
across the varied stall timing.

Functional coverage is omitted from Step 5 because Step 4 completed 100% closure. Every seed passes,
so no separate failure-reproduction log or debugging waveform is generated.
