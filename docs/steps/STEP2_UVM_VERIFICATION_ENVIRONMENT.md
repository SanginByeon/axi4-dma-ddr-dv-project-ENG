# Step 2 — UVM-Based Verification Environment

## Overview

Convert the Step 1 directed testbench into a UVM verification environment composed of Transactions,
Sequences, a Driver, Monitor, Scoreboard, Agent, Environment, and Test.

Reproduce the four normal Step 1 transfers with the same addresses and sizes, inject a verification
pattern into each source-memory region, and check data integrity across every transferred location.
Preserve the DUT and DDR memory model's AXI4 behavior and the functional coverage model while removing
the DDR memory model's previous reset-based pattern initialization.

## Objective

Improve the verification environment's reuse and extensibility by separating stimulus generation,
DUT driving, behavior observation, and result evaluation into individual UVM components.

## File Organization

| File | Role |
|---|---|
| `design.sv` | Top-level source file for design compilation that includes the AXI4 interface, DMA controller, and DDR memory model |
| `axi4_if.sv` | Define AXI4 channel signals and master/slave modports |
| `dma_controller.sv` | DUT that performs AXI4-based memory copies |
| `ddr_memory_model.sv` | Verification memory model that responds to DUT AXI4 requests |
| `mmio_if.sv` | Group MMIO register-access and interrupt signals and define TB/DUT modports |
| `coverage.sv` | Measure transfer-size, FSM-state, address-alignment, burst-length, state-transition, and cross coverage |
| `testbench.sv` | Connect DUT/interfaces, provide virtual interfaces, and run the UVM test |
| `utility_pkg.sv` | Provide MMIO access, DMA-completion wait, source-memory preload, and DDR backdoor read |
| `dma_tx.sv` | Sequence item containing DMA settings, constraints, and the payload used to preload the source |
| `dma_base_seq.sv` | Base sequence for DMA transaction generation and randomization |
| `dma_s1_seq.sv` | 256B basic-copy sequence |
| `dma_s2_seq.sv` | 1024B large-copy sequence |
| `dma_s3_seq.sv` | 16B and 64B small-copy sequence |
| `dma_driver.sv` | Convert transactions into MMIO stimulus and check DMA execution results |
| `dma_monitor.sv` | Reconstruct DMA transactions by observing MMIO writes and interrupts |
| `dma_scoreboard.sv` | Compare source/destination memory and check the expected transaction count |
| `dma_agent.sv` | Create the Monitor and add/connect the Sequencer and Driver in active mode |
| `dma_env.sv` | Create the Agent and Scoreboard and connect the analysis port |
| `dma_test.sv` | Configure the UVM environment, run sequences, and report coverage and results |

## Main Changes

- Replace the task-based scenarios with UVM sequences that generate DMA transactions
- Use the UVM phase system to structure environment creation/connection, reset, stimulus execution, result checking, and reporting
- Pass MMIO/AXI4 virtual interfaces to UVM components through `uvm_config_db`
- Connect the Sequencer and Driver inside the active Agent while allowing the Monitor to observe transactions independently
- Standardize the verification procedure so the Driver checks `STATUS` and logs `BYTES_DONE` for
  each transaction
- Abstract DMA configuration into `dma_tx` and define constraints for 4-byte alignment, the 4 KB memory range, and non-overlapping transfer regions
- Remove the DDR memory model's reset-based pattern initialization and transfer memory-initialization
  responsibility to the UVM Sequence, which backdoor-preloads each source region with the verification
  data pattern generated by `dma_tx` before the scenario runs
- Implement a Scoreboard that uses addresses and sizes collected by the Monitor to compare the complete source/destination transfer region in 32-bit words
- Treat X/Z data as a verification failure in the Scoreboard and check that expected and actual transaction counts match
- Convert progress logs in `testbench.sv` and `utility_pkg.sv` from `$display` to `uvm_info` so verbosity controls their output
- Configure UVM hierarchy verbosity centrally in `dma_test.sv` and provide a UVM report summary

## Test Scenarios

Run the four normal Step 1 transfers in the same order.

| No. | Scenario Name |
|---:|---|
| S1 | 256B basic copy (`0x0000` → `0x0400`) |
| S2 | 1024B large copy (`0x0100` → `0x0800`) |
| S3-1 | 16B small copy (`0x0200` → `0x0300`) |
| S3-2 | 64B small copy (`0x0210` → `0x0310`) |

## VCS Configuration

- Simulator: Synopsys VCS 2025.06
- UVM version: UVM 1.2
- Compile options:

  ```text
  -timescale=1ns/1ns +vcs+flush+all +warn=all -sverilog -debug_access+all
  ```

- Run options: none
- Add `-debug_access+all` to the default configuration so `uvm_hdl_deposit()` and `uvm_hdl_read()` can access the DDR memory model through the backdoor.
